## Как обновляемся

Клиент больше не обновляет себя сам: иначе новая версия стирала бы мод.
Порядок такой — мод смотрит версию клиента у Яндекса и наши релизы, и:

- вышел клиент, сборка мода под него готова → предлагает «Обновить клиент
  и мод»: качает официальный установщик Яндекса, ставит клиент, кладёт
  поверх наш `app.asar`, чинит проверку целостности и перезапускается;
- вышел клиент, сборки ещё нет → держит прежнюю версию и говорит об этом;
  автосборка поднимает мод в течение трёх часов;
- клиент тот же, а мод обновился → обновляет только `app.asar`.

Выключается тумблером «Обновлять клиент вместе с модом» в настройках.

## Отложено

- [ ] **Скробблинг Last.FM.** Нужен ключ приложения Last.FM.
- [ ] **Врезки, которые реже ломаются от обновлений клиента.** Ждём, пока
      наберётся статистика: из трёх версий клиента (5.119, 5.120, 5.121.2)
      врезку сломала только 5.121.2 — Яндекс переписал `checkExperiment`.
      Что можно сделать, по порядку:
      1. Меньше врезок в код клиента. Например, «управление с телефона»
         включать подменой ответа сервера со списком экспериментов, а не
         правкой `checkExperiment`: формат ответа стабильнее кода.
         Пройтись так по всем восьми врезкам.
      2. Запасные шаблоны: у каждой врезки два-три варианта поиска места.
      3. Автопочинка: при поломке сборка запускает Claude в GitHub Actions,
         он правит врезку и открывает pull request, проверки его подтверждают.
         Нужен ключ Anthropic API, запуски платные.
      Пользователей поломка не задевает: мод держит прежний клиент, пока
      под новый нет сборки.

## Не делаем

- **Скачивание треков.** Требует расшифровки защищённого потока — это снятие
      технической защиты, а не сохранение того, что клиент получает открытым.
